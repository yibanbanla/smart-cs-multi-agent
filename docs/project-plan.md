# 智能客服多Agent系统项目规划

## 一、项目定位

这是一个以 Python 为核心实现的多 Agent 智能客服项目，目标是提供一个可运行、可讲解、可扩展的企业级示例。

适用场景：

- 金融、电商等带知识问答和合规要求的客服场景
- 多 Agent 编排学习与演示
- 面试项目展示与系统设计讲解

## 二、当前架构方向

核心架构采用 Supervisor 编排模式：

- Supervisor 负责统一路由与结果汇总
- 知识检索 Agent 负责 RAG 问答
- 工单处理 Agent 负责工单创建与流转
- 合规审查 Agent 负责规则和语义双重审查

配套能力：

- 工作记忆、短期记忆、长期记忆
- MCP 工具协议层
- OpenTelemetry 追踪

## 四、技术亮点

### 4.1 Supervisor 编排

- 中央协调，流程更可控
- 适合在固定节点插入合规检查
- 便于扩展新业务 Agent

### 4.2 分层记忆

- 工作记忆：单次请求上下文
- 短期记忆：会话级上下文
- 长期记忆：知识库与历史信息

### 4.3 RAG 检索

- Query 改写
- Top-K 检索
- 重排序
- 文档约束生成

### 4.4 工具标准化

- 基于 MCP 风格接口封装工具
- 统一注册、发现、调用

### 4.5 可观测性

- Agent 级别耗时
- 工具调用日志
- 路由链路与失败率

## 五、面试表达重点

- 为什么 Supervisor 比简单 if-else 更适合复杂流程
- 为什么客服场景需要分层记忆
- 为什么 RAG 能降低幻觉风险
- 为什么要把工具调用抽象成 MCP 协议层
- 如何用 OpenTelemetry 排查 Agent 链路问题

## 六、后续可扩展方向

- 增加更多业务 Agent
- 支持混合检索
- 引入流式输出
- 增加评估集和自动化质量回归
