## 智能客服多Agent系统 | 核心开发者 | 2025.09 - 2026.03

**项目背景**：面向金融/电商场景的企业级智能客服系统，采用多 Agent 架构替代传统单体机器人，支撑高频咨询、知识问答、工单流转与合规审查。

**核心职责**：

- 设计并实现基于 **Supervisor 编排模式** 的多 Agent 协作架构，包含意图路由、知识检索、工单处理、合规审查等核心能力
- 构建 **分层记忆系统**，以工作记忆、Redis 短期记忆、FAISS 长期记忆支撑多轮对话与知识检索
- 实现完整 **RAG 流程**，包含 Query 改写、向量检索、重排序和上下文注入，提升知识问答准确率
- 基于 **MCP 工具协议** 封装订单查询、工单创建、风控检查等外部能力，统一工具注册与调用方式
- 集成 **OpenTelemetry 全链路追踪**，实现 Agent 调用链路、耗时与工具调用日志的可观测化

**技术栈**：Python / LangGraph / FastAPI / Redis / FAISS / OpenTelemetry / Docker

**项目成果**：

- 首问解决率从 65% 提升至 82%
- 平均响应时间从 30 分钟降至 3 秒
- 通过分层记忆和上下文裁剪将 Token 消耗降低 40%
- 建立合规审查链路后，敏感回复风险显著下降

## 简历写法建议

### 动词选择

- 用“设计并实现”替代“参与开发”
- 用“搭建”替代“协助搭建”
- 用“优化并提升”替代“做了优化”

### 量化表达

- 性能：响应时间、P99、吞吐
- 业务：首问解决率、满意度、人工转接率
- 成本：Token 降幅、资源占用
- 质量：准确率、误判率、故障恢复时间

### 面试时可强调的亮点

- 不只是调 API，而是完整的多 Agent 编排系统
- 有 RAG、记忆、工具协议、追踪、合规等完整工程链路
- 既能讲业务价值，也能讲底层实现
